# Proposal

## Why

v4.6 的高情商回复页在真实数据下暴露出三个体验问题：

1. **上下文挤在一起**：三栏工作区各自限制高度（会话列 56vh、上下文列 60vh），页面本身还在滚动；上下文一次性渲染最近 30 条并对每条做 3 行截断，窄窗口下气泡被压得又短又挤，看不出是「消息列表」。
2. **读取慢**：常驻回复运行时是单线程串行处理，`chat.context` 每次都要重新解密 `session.db`、`user.db` 并读取消息快照；页面每 30 秒的轮询还会和点击请求排队。首次打开要整库解密，之后每次切换会话也要重走一遍，体感是「点一下要等」。
3. **左侧会话名仍会显示自己**：企微 `conversation_table` 的私聊标题有时存的是当前登录账号的名字；当前取名逻辑把自己的名字当正常标题返回，导致左侧列表出现自己的名字，而不是对方或群名。

本变更把上下文改成固定高度、默认停在最新消息的滚动视口，补齐向上分页与缓存/预热，并修正私聊/群聊的取名来源。

## What Changes

- **上下文视口重构（BREAKING 行为变化）**
  - 工作区高度按可见区域固定，只有上下文消息区在滚动；页面不再整体滚动。
  - 默认只加载最近 **20** 条（6 小时窗口，静默会话回退最近 30 天），进入会话即滚到最底部展示最新消息。
  - 向上滚动到顶部时按「更早一页」继续加载（每页 20 条），保持滚动位置；新消息到达时若用户停留在底部则自动跟随，否则显示「跳到最新」。
  - 长消息不再统一截 3 行：在滚动视口内完整展示，仅超长消息保留「展开/收起」。
- **左侧会话名称修复**
  - 私聊：优先显示**对方**名称（会话 ID 后缀 → 通讯录/外部联系人备注/成员昵称）；企微标题若等于当前账号自己的名字则忽略；仍无法解析显示「私聊会话」。
  - 群聊：显示群名/群备注，不使用直聊取名逻辑。
  - 识别「自己」：用直聊会话 ID 前缀匹配 `user_table.account`；若账号信息不可用，用「同一直聊标题在多个会话重复出现」作为兜底判定。
- **读取性能**
  - 运行时缓存「会话目录」（session.db 行 + 成员昵称 + 用户映射，TTL 30 秒）与「每会话上下文」（TTL 10 秒），手动刷新/首次加载可强制绕过。
  - 打开页面、列表返回后后台预热消息快照（最新会话），让首次点击命中已解密数据。
  - 上下文首屏只取 20 条、按需分页；前端按会话缓存上下文（切回旧会话立即显示旧内容再静默刷新），轮询让路于用户点击。
  - 目标：缓存命中时切换会话体感秒开；首次打开不再因重复解密而叠加等待。
- **不变更**：图片处理方式（生成时把图片交给模型）、生成/复制流程、图片不在加载时 OCR；上下文里不新增「我」标记（本轮明确不做）。

## Capabilities

### Modified Capabilities

- `wecom-high-eq-reply`：修改「最近会话自动列表」「只读上下文与自动刷新」，删除过时的「图片消息 OCR 进入上下文」并新增「图片消息在生成时交给模型」，新增「上下文读取性能与缓存」。

## Impact

- **前端**：`src/pages/wecom/HighEqReplyPage.tsx`、`highEqReply.logic.ts`、`highEqReply.css` 及测试；工作区布局、滚动/分页、会话缓存、刷新让路。
- **后端**：`worker/reply_runtime/message_source.py`（目录/上下文缓存、预热、分页、取名）、`worker/reply_runtime/runtime.py`（`chat.recent` / `chat.context` 参数与返回字段）、`worker/wecom/local_db.py`（会话行读取、自己的身份识别、取名辅助）。
- **测试**：Python 单测覆盖取名优先级、缓存命中/失效、分页 `hasMore`、预热；前端 vitest 覆盖分页合并、滚动到底部/跳到最新、会话缓存、命名回退。
- **文档与发布**：README / docs 同步滚动与名称规则；版本升到 `4.6.4`，由 GitHub Actions 在线构建并通过 tag 发布 Release（本机不打包）。
- **兼容性**：`chat.recent` / `chat.context` 仅新增可选参数与返回字段，旧调用保持兼容；图片、生成、提示词库行为不变。
