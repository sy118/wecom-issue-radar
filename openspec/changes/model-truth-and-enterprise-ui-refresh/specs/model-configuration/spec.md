# Spec Delta

## Purpose

定义全局模型配置在桌面端各处展示与生效的行为契约：用户在全局设置中保存的模型，必须成为个人微信配置中心、企业微信模型能力卡片与群监听/拟稿运行时的唯一事实来源，任何界面都不得把过期快照当作当前模型展示。

## ADDED Requirements

### Requirement: 全局模型设置为唯一事实来源

系统 SHALL 以用户保存的全局模型配置（Base URL、模型名称、协议）作为所有界面与运行时的当前模型来源；任何派生存储（个人微信 provider 快照、模型能力检测结果）仅为缓存，不得覆盖当前值。

#### Scenario: 保存新模型后各处一致

- **WHEN** 用户在全局设置中把模型名称从 `qwen3.7-max` 改为 `deepseek-v4.1-flash` 并保存
- **THEN** 个人微信配置中心、企业微信模型能力卡片与项目编辑中的模型展示均显示 `deepseek-v4.1-flash`
- **AND** 不再出现 `qwen3.7-max` 作为当前模型

#### Scenario: 未配置模型时的空状态

- **WHEN** 全局模型配置的 Base URL 或模型名称为空
- **THEN** 各配置中心显示"尚未配置模型"的明确空状态，而不是上一次的旧模型名

### Requirement: 个人微信默认模型连接随全局设置同步

系统 SHALL 在个人微信 worker 每次启动或重新加载配置时，用当前全局模型配置刷新默认模型连接（`llm-default`）的协议、Base URL、模型名称、温度与最大输出 token；已保存的 API Key 与用户自建的其它模型连接 MUST 保持不变。

#### Scenario: 已有默认连接时更新

- **WHEN** 个人微信数据库已存在 `llm-default` 连接且全局模型已变更
- **THEN** 刷新后该连接的模型名称与 Base URL 等于全局设置当前值
- **AND** 该连接的密钥状态仍为"密钥已保存"

#### Scenario: 用户自建连接不受影响

- **WHEN** 个人微信中存在用户自建的 provider（非 `llm-default`）
- **THEN** 同步过程不修改其名称、模型或密钥

### Requirement: 个人微信配置中心展示当前模型与来源

个人微信配置中心 SHALL 以实时全局模型配置渲染「模型连接」卡片，并标注模型来源为全局设置；当实时配置不可用时，才回退到默认连接快照并说明其为缓存。

#### Scenario: 配置中心标注来源

- **WHEN** 用户打开个人微信配置中心且全局模型已配置
- **THEN** 「模型连接」卡片显示当前模型名称，并带有"来源：全局设置"标识

#### Scenario: 刷新后立即反映

- **WHEN** 用户在其它页面修改并保存全局模型后返回个人微信配置中心
- **THEN** 卡片显示新模型，无需重启应用

### Requirement: 模型能力卡片区分当前模型与过期检测

企业微信「设置 → 模型与 OCR → Agent v2 模型能力」SHALL 在配置指纹与上次检测不一致时，主标签只展示当前全局模型；上次检测的模型信息 MUST 标注为过期/历史结果，不得以当前值的样式呈现。

#### Scenario: 配置变化后卡片主值更新

- **WHEN** 全局模型从 `qwen3.7-max` 改为 `deepseek-v4.1-flash` 且尚未重新检测能力
- **THEN** 卡片主值显示 `deepseek-v4.1-flash` 并提示配置已变化
- **AND** `qwen3.7-max` 仅作为"上次检测"信息出现或不再展示

#### Scenario: 重新检测后恢复一致

- **WHEN** 用户点击"检测全部能力"且检测成功
- **THEN** 卡片显示检测结果与当前模型配置一致，并展示当前模型名称
