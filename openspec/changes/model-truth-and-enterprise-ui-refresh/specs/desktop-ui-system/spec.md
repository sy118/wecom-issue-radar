# Spec Delta

## Purpose

定义桌面应用的企业级极简视觉与组件系统：以单层语义 token 统一颜色、字号、间距、圆角、阴影与动效，统一壳层与共享组件状态，并在浅色/深色、键盘操作与界面缩放下保持一致的可用性与可访问性。

## ADDED Requirements

### Requirement: 单层语义化 design token

界面 SHALL 由一层语义 token 驱动：背景/表面/文字/边框/主色/语义状态色、字号与行高、4px 间距刻度、圆角、2 级阴影与动效时长；浅色与深色 MUST 成对定义，页面样式不得新增脱离 token 的硬编码颜色或任意间距体系。

#### Scenario: 深浅色使用同一套 token

- **WHEN** 用户在标题栏切换浅色/深色主题
- **THEN** 所有页面仅通过 token 变化切换配色，正文与次要文字对比度均不低于 4.5:1

#### Scenario: 页面不引入新硬编码色

- **WHEN** 审查任一页面样式
- **THEN** 颜色、间距、圆角、阴影均引用 token，未出现新的散落十六进制颜色值

### Requirement: 统一壳层与页头模式

应用 SHALL 使用统一的窗口壳层：固定标题栏、可折叠侧边导航（分组与选中态清晰）、统一页头（面包屑/眉题、标题、描述、主次操作）与单一页面滚动容器；内容宽度与区块间距 MUST 遵循统一节奏，长页面不得出现双滚动条。

#### Scenario: 页面切换保持单一滚动

- **WHEN** 用户在任意页面之间切换并滚动
- **THEN** 只有页面主内容区滚动，侧边导航与标题栏固定不动
- **AND** 切换页面后焦点落在主内容区

#### Scenario: 页头主操作唯一

- **WHEN** 用户进入任一功能页
- **THEN** 页头只有一个主按钮，次级操作以次级按钮或菜单呈现

### Requirement: 共享组件状态一致

共享组件（按钮、输入框、字段、卡片、状态标签、抽屉/弹窗、空状态、统计块）SHALL 具备一致且可辨识的 hover、focus、active、disabled、loading、error 状态；危险操作 MUST 使用语义危险色并与主操作分离。

#### Scenario: 键盘焦点可见

- **WHEN** 用户仅使用键盘 Tab 遍历交互元素
- **THEN** 每个可聚焦控件都显示清晰的焦点环，且焦点不会被固定条或弹层遮挡

#### Scenario: 危险操作与主操作分离

- **WHEN** 用户查看删除类操作
- **THEN** 该操作使用危险色，与同区域主操作在视觉和位置上分离，并在执行前要求确认

### Requirement: 可访问性与缩放基线

交互目标 SHALL 不小于 24×24 CSS 像素（桌面端关键操作建议 44px），图标按钮 MUST 提供可访问名称；动效 MUST 尊重 `prefers-reduced-motion`；界面在 1024×700 最小窗口与 80%–150% 缩放下 MUST 不裁切、不横向滚动、不重叠。

#### Scenario: 缩减动效生效

- **WHEN** 操作系统开启"减少动态效果"
- **THEN** 页面过渡与装饰动效降级为无动画或淡入，功能不受影响

#### Scenario: 最小窗口不裁切

- **WHEN** 窗口缩小到 1024×700
- **THEN** 导航、页头、表单与主操作均可见可操作，没有内容溢出到窗口外

### Requirement: 视觉验收可复现

前端 SHALL 提供可复现的界面预览与截图能力，覆盖浅色与深色主题下的关键页面，用于改动前后的视觉对照与回归验收。

#### Scenario: 生成浅深色对照截图

- **WHEN** 开发者在本地运行预览脚本
- **THEN** 脚本输出关键页面的浅色与深色截图，并能用于识别布局溢出、对比度不足与组件状态缺失
