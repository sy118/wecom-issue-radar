# Spec Delta

## Purpose

以 Electron 提供应用桌面外壳，负责窗口、单实例、后台进程、数据位置、自动更新与旧版本迁移，使业务功能在换壳后对用户保持连续可用。

## ADDED Requirements

### Requirement: 桌面窗口与单实例
应用 SHALL 以无边框窗口启动，提供自绘标题栏的最小化、最大化/还原与关闭操作，并在重复启动时聚焦已有窗口而不是创建第二个实例。

#### Scenario: 重复启动
- **WHEN** 应用已在运行且用户再次双击快捷方式
- **THEN** 现有窗口被还原、显示并获得焦点，不产生第二个进程实例

#### Scenario: 窗口缩放与拖拽
- **WHEN** 用户拖拽标题栏或双击标题栏
- **THEN** 窗口移动或最大化/还原，标题栏按钮区域不触发拖拽

### Requirement: 业务数据位置保持兼容
应用 SHALL 继续把业务数据存放在用户主目录下的既有数据根（`~/.wecom-issue-radar`），不得把配置、数据库、日志或导出结果放入 Electron 的 userData 目录。

#### Scenario: 升级后读取旧数据
- **WHEN** 已安装 v3.5.3 的用户首次启动 v4.0.0
- **THEN** 应用直接读取原配置、回复运行时数据库与日志，用户无需重新配置

#### Scenario: 全新安装
- **WHEN** 用户在空白机器上首次启动
- **THEN** 应用在既有数据根创建默认配置与数据库，并展示可完成的引导

### Requirement: 后台进程生命周期
应用 SHALL 以单一常驻 Python sidecar 提供长驻运行时，并按需启动一次性任务进程；应用退出、崩溃或安装更新时 SHALL 结束所有子进程（含进程树），不得残留孤儿进程。

#### Scenario: 正常退出
- **WHEN** 用户关闭主窗口并退出应用
- **THEN** 常驻 sidecar 与所有一次性任务进程被终止，临时请求文件被清理

#### Scenario: 安装更新前拦截
- **WHEN** 用户确认安装更新时仍有任务在运行
- **THEN** 应用阻止安装并提示等待任务结束，不强行杀死任务

### Requirement: 自动更新
应用 SHALL 通过 GitHub Release 检查、下载并安装更新；下载与安装必须由用户确认，更新失败不得损坏本地配置或数据库。

#### Scenario: 有新版本
- **WHEN** 启动后检测到更高版本且用户点击更新
- **THEN** 应用显示下载进度并在完成后提示重启，重启后版本号更新

#### Scenario: 更新清单不可用
- **WHEN** 检查更新失败或网络不可达
- **THEN** 应用保持当前版本可用并给出可重试的提示，不阻塞主流程

### Requirement: 旧版本迁移提示
应用 SHALL 检测机器上是否存在旧 Tauri 版本的安装，并在首次启动时引导用户完成手动迁移，且明确告知业务数据不会丢失。

#### Scenario: 检测到旧版
- **WHEN** v4 首次启动且发现旧版安装记录
- **THEN** 应用展示一次性迁移说明，提供旧版卸载与新版下载入口，并在用户确认后继续

#### Scenario: 旧客户端检查更新
- **WHEN** 旧 Tauri 客户端向 Release 请求更新清单
- **THEN** 返回指向最后一版 Tauri 安装包的兼容清单，旧客户端不报错也不误装 Electron 包

### Requirement: 本地安全边界
应用 SHALL 在渲染进程中禁用 Node 集成并启用上下文隔离与沙箱，只通过 preload 暴露白名单能力；文件读写命令 MUST 限制在用户通过系统对话框选择的路径或应用数据根内。

#### Scenario: 渲染层越权调用
- **WHEN** 页面脚本尝试调用未在白名单中的主进程能力
- **THEN** 调用被拒绝，应用继续正常运行

#### Scenario: 打开外部链接
- **WHEN** 页面尝试导航到非应用内地址
- **THEN** 导航被阻止，应用不加载任意远程页面
