# Design

## Context

「常用与高级」由 `SettingsHome` 维护常用模式草稿，并在高级模式嵌入 `SettingsPage`。`SettingsPage` 自己的 `page-title-row` 包含「保存设置」按钮，但 `src/nav.css` 用 `.settings-advanced-embed > .settings-page > .page-title-row { display:none; }` 把整行隐藏；常用模式保存按钮只提交 `SettingsHome` 的草稿，高级页的草稿因此没有保存入口。

高情商回复页面已经支持选中 0–N 条消息、本群提示词和长期角色补充；生成 payload 目前包含 `text/context/recipient/promptId/promptNote/focusMessages/imageMessageIds`，没有一次性的补充说明。

## Goals / Non-Goals

**Goals：** 高级设置随时可保存、状态可见、切换不丢修改；高级页视觉与常用页一致；高情商回复可临时补充本次要求且不进入长期配置。

**Non-Goals：** 不重写设置页的数据模型；不把「本次补充要求」持久化到群；不改变提示词 JSON 输出契约；不改变选中消息/图片的现有行为。

## Decisions

### D1 高级设置保存壳层

- `SettingsPage` 增加 `embedded?: boolean`（或等价参数）：
  - 非嵌入模式保持现有整页页头；
  - 嵌入模式渲染紧凑工具栏：标题「高级设置」、说明、保存状态、`保存设置` 按钮。
- 删除 `src/nav.css` 中隐藏 `.page-title-row` 的规则，不再使用脆弱局部 hack。
- `SettingsPage` 继续持有自己的 `draft` 和 `save()`；保存成功仍调用现有 `onSave`。
- 工具栏按钮在 `!dirty || saving` 时禁用；dirty 时显示「● 有未保存修改」，保存后显示「已保存」。
- 底部在窄窗口/长表单显示吸底保存条，复用同一 `save()`；与顶部按钮共享 loading/disabled 状态。
- `SettingsPage` 通过 `onDirtyChange` 向 `SettingsHome` 暴露 dirty；`SettingsHome` 在常用/高级切换时若有任一草稿未保存，弹出确认（继续切换/取消）。`SettingsPage` 自己已有 `useUnsavedChanges`，保留并在嵌入模式生效。

### D2 高级页视觉

```
+---------------------------------------------------------------+
| 设置                                      [常用] [高级]       |
+---------------------------------------------------------------+
| 高级设置   配置数据源、模型、腾讯文档与诊断      [保存设置]   |
|              ● 有未保存修改                                  |
+---------------------------------------------------------------+
| [企业微信与目录] [模型与 OCR] [腾讯文档] [诊断与日志]          |
+---------------------------------------------------------------+
| + card -----------------------------------------------------+ |
| | SectionHeader + 两列表单                                   | |
| +-----------------------------------------------------------+ |
+---------------------------------------------------------------+
```

- 最大内容宽度与常用模式一致（约 1000px），页面单一滚动容器。
- tabs 使用统一 segmented 样式；≤900px 时允许横向滚动或 2×2 换行，不挤压文字。
- 卡片使用统一 `settings-section`/`glass-card` 间距 16px，内部字段两列，窄屏单列。
- 「配置备份与迁移」从环境 tab 的顶部移到独立卡片，避免与数据目录设置混排。
- 深色模式、1024×700 验收：无横向滚动、无按钮被裁切、保存入口可见。

### D3 高情商回复「本次补充要求」

- 页面状态：`replyInstruction`（string，trim；≤500 字）。
- UI 位置：待回复消息面板之后、对方称呼之前：
  - label「本次补充要求（可选）」；
  - textarea 2–3 行，显示字数；
  - hint「只影响这一次生成，不是发给对方的消息」；
  - 清空按钮。
- 切换会话时清空；生成成功/失败后保留，便于「重新生成」时微调；应用重启不保留。
- 手动输入模式同样可用；补充要求不替代手动粘贴的对方消息。
- payload 增加 `replyInstruction`（非空才带），`eqReplyPayload` 负责 trim 和 500 字截断。
- 后端 `action_eq_reply` 读取 `replyInstruction`，传给 `prompts.eq_reply_prompt`；prompt 增加：
  ```
  本次回复的补充要求：
  <instruction>
  ```
  放在「需要回复的消息」之后、「沟通对象/相关上下文」之前，保持 JSON 契约不变。
- 不新增数据库字段或配置项；不进入「本群角色补充」。

### D4 测试

- 前端：高级保存按钮在嵌入模式可见；dirty 状态、切换确认、吸底保存条；补充要求 payload、500 字截断、切换会话清空、重新生成保留。
- 后端：`replyInstruction` 注入 prompt；空值不改变 prompt；结果字段和 JSON 契约保持。
- 视觉：1024/深色截图，检查 tabs、保存条、补充输入框无溢出。

## Risks / Trade-offs

- 吸底保存条可能遮挡内容 → 内容区留出底部 padding；只在高 dirty/窄窗口显示。
- 两套保存入口（顶部 + 底部）需要共享同一 dirty/saving 状态，避免重复提交。
- 切换模式确认可能增加一次点击 → 只在 dirty 时出现。
- 补充要求属于用户输入，模型可能不完全遵循 → UI 用「补充要求」而非「必须原样写入」，并保持草稿可编辑。
