# Proposal

## Why

v4.6.4 的「高情商回复」左侧仍是自动列出全部最近会话，无法把不关心的工作群/机器人会话排除，也无法给会话起本地别名；用户实际只想同步自己关心的少数会话。另一个问题是「待回复对象」只能选一条消息，但群聊里经常需要同时回应多个人/多个问题，逐条生成再人工合并很费事。

本变更把会话列表改成用户自己维护的清单（搜索添加、改名、移除、只同步已添加），并让群聊可以选 0~N 条消息综合生成回复。

## What Changes

- **会话清单改为用户维护**
  - 左侧只展示用户显式添加的会话；未添加的会话不出现在高情商回复页，也不会被轮询/同步。
  - 「添加会话」弹窗从全部最近会话（群聊 + 私聊，最多 300 个）搜索、多选添加；支持移除。
  - 支持本地别名（重命名），只保存在本机，不修改企微原始数据库；列表优先显示别名，其次对方/群名。
  - 已添加会话按最后消息时间自动排序（最新在前）；清单为空时显示引导添加的空态。
- **群聊多消息回复**
  - 私聊：默认选中最后一条消息（保持一对一习惯），可取消或加选。
  - 群聊：默认不选中任何消息，直接结合群聊上下文生成；点击消息可加选/取消，选中多条时作为「需要回复的消息列表」交给模型，综合回复而不是逐条机械回复。
  - 支持 0 条选中直接生成（使用当前上下文）；手动输入仍可覆盖选中消息。
  - 选中消息里的图片随生成请求一起交给模型（沿用最多 6 张、视觉失败回退纯文本的规则）。
- **持久化与同步**
  - 会话清单（`conversationId + 本地别名 + 添加时间`）存到常驻回复运行时的 SQLite，重启保留；通过带 revision 的运行时命令增删改，避免并发覆盖。
  - 未添加会话不参与 `chat.recent` 轮询与上下文读取；新增会话后按需读取其最近消息。

## Capabilities

### Modified Capabilities

- `wecom-high-eq-reply`：移除「最近会话自动列表」，新增「我的会话列表」「会话目录搜索与添加」，改写「回复对象选择」以支持 0~N 条多选综合回复。

## Impact

- **后端**：`worker/reply_runtime/store.py`（新表 `reply_assistant_chats`）、`runtime.py`（`chat.chats.add/rename/remove` 命令、`chat.catalog` 查询、`chat.recent` 只返回已添加会话并带 revision）、`message_source.py`（目录全量搜索 + 已添加会话时间/名称合并）、`worker/reply_assistant/{actions,prompts}.py`（多消息 `focusMessages`）。
- **前端**：`src/pages/wecom/HighEqReplyPage.tsx`、`highEqReply.logic.ts`、`highEqReply.css`、测试；新增添加/重命名弹窗、多选目标面板与生成 payload。
- **测试**：Python 覆盖清单持久化、命令 revision/幂等、catalog 搜索、已添加过滤、多消息 prompt 与回退；前端覆盖多选、0 选中生成、别名显示、添加/移除/改名、图片并集。
- **文档与发布**：README / docs / CHANGELOG；版本升到 `4.6.5`，GitHub Actions 在线构建并 tag 发布（本机不打包）。
- **兼容性**：会话清单为空时页面不自动选会话；旧版自动列表不再出现。已添加的会话读取链路不变；图片/生成/复制/提示词库行为不变。
